# 从 0.6 迁移到 1.0

[English](0.6-to-1.0.md) · [迁移](README.zh.md)

PACE 1.0 仍在开发中。本指南随之扩充：每个预发布版本都会补充需要你修改代码的变化。这里没有列出的内容都保持原样，
无需改动。

## 1.0.0-alpha.1：模块布局

库现在按模块组织。行为和签名都没有变化；变化的是头文件路径、xmake target 和具名模块接口。

### 头文件路径

每个模块有一个伞头 `<pace/<module>.hpp>`，内容头文件位于 `include/pace/<module>/`。最简单的更新方式是为用到的每个
模块包含它的伞头。

| 0.6 | 1.0 |
|:--|:--|
| `<pace/task.hpp>`、`<pace/io_context.hpp>`、`<pace/run.hpp>`、`<pace/cancellation.hpp>`、`<pace/task_group.hpp>`、`<pace/operation.hpp>`、`<pace/this_context.hpp>`、`<pace/blocking.hpp>`、`<pace/platform.hpp>`、`<pace/io_backend.hpp>` | `<pace/runtime.hpp>`，或 `<pace/runtime/…>` 下的同名文件 |
| `<pace/runtime.hpp>`（`pace::runtime` 类） | `<pace/runtime.hpp>` 现在包含整个运行时；只要这个类则用 `<pace/runtime/runtime.hpp>` |
| `<pace/tcp.hpp>`、`<pace/udp.hpp>`、`<pace/ip.hpp>`、`<pace/stream_io.hpp>` | `<pace/net.hpp>`，或 `<pace/net/tcp.hpp>` 等 |
| 用于 HTTP/1.1 的 `<pace/http.hpp>`（`http::app`、`get`、`serve`、客户端） | **`<pace/http1.hpp>`**。`<pace/http.hpp>` 现在是与协议无关的 HTTP 模块 |
| `<pace/http_types.hpp>`、`<pace/http_router.hpp>` | `<pace/http.hpp>`，或 `<pace/http/types.hpp>`、`<pace/http/router.hpp>` |
| `<pace/http_services.hpp>` | `<pace/gateway.hpp>` |
| `<pace/networking.hpp>`、`<pace/extensions.hpp>`、`<pace/application.hpp>` | 已移除：包含你用到的模块头文件，或用 `<pace/pace.hpp>` 包含所有已启用的模块 |
| `<pace/tls.hpp>`、`<pace/dns.hpp>`、`<pace/quic.hpp>`、`<pace/http2.hpp>`、`<pace/http3.hpp>`、`<pace/websocket.hpp>`、`<pace/net.hpp>`、`<pace/pace.hpp>` | 不变 |
| `<pace/detail/…>` | 已移除。它们从来不是公开接口，现在位于库的源码中 |

唯一一处包含语句本身仍能编译、含义却已改变的是 `<pace/http.hpp>`：原本用它来使用 HTTP/1.1 的代码，现在会因为
缺少 `pace::http::app` 或 `pace::http::get` 之类的名字而编译失败。请改为包含 `<pace/http1.hpp>`。

`pace::detail` 命名空间已不存在。直接使用它的代码依赖的是内部实现，没有替代品。

### xmake target

每个模块都是一个独立的静态库，依赖关系明确，因此依赖某一个模块时只会构建该模块及其所需的部分。

| 0.6 | 1.0 |
|:--|:--|
| `pace_runtime`、`pace_net`、`pace` | 不变 |
| `pace_extensions` | 已移除：按需依赖 `pace_tls`、`pace_dns`、`pace_quic` |
| `pace_application` | 已移除：按需依赖 `pace_http1`、`pace_http2`、`pace_http3`、`pace_websocket` |
| — | 新增：`pace_http`，仅头文件，包含与协议无关的 HTTP 类型和路由器；由各 HTTP 模块自动引入 |

网关（`<pace/gateway.hpp>`）目前编译在 `pace_http1` 中。

### 具名模块

`import pace;` 仍然导入所有已启用的内容。现在每个库模块还各有一个具名模块：`pace.runtime`、`pace.net`、
`pace.http`、`pace.http1`、`pace.gateway`、`pace.tls`、`pace.dns`、`pace.quic`、`pace.http2`、`pace.http3`、
`pace.websocket`。每个具名模块只导出自己的名字，因此使用 TCP 的程序要同时导入 `pace.runtime` 和 `pace.net`。
target 仍是 `pace_module`，用 `--modules=y` 构建。[构建选项](../reference/build-options.zh.md)

### 兼容别名

`tcp_stream`、`tcp_listener`、`ipv4_endpoint` 和 `listen_options` 仍可从 `<pace/net.hpp>`
（`<pace/net/aliases.hpp>`）使用，但已弃用（目前还没有编译器警告）：请改用 `pace::tcp::stream`、`pace::tcp::listener`、
`pace::tcp::endpoint` 和 `pace::tcp::listen_options`。它们将在之后的某个 1.0 预发布版本中移除，届时会在这里列出。

## 1.0.0-alpha.2：运行时与网络层

### `task_group::cancel()` 让作用域正常结束

用任务组自己的 `cancel()` 取消后，作用域现在正常返回，不再抛出 `operation_canceled`：有返回值的主体返回它的值，
`void` 主体直接返回。原先在调用 `cancel()` 之后、围绕 `task_group::run` 或 `with_task_group` 捕获
`operation_canceled` 的代码，可以去掉这段处理。有返回值的主体若在产生值之前就被取消，仍会抛出；来自任务组外部的
取消（外层的 `with_cancellation`、截止时间、`io_context::stop()`）照旧传播。
