# 从 0.6 迁移到 1.0

[English](0.6-to-1.0.md) · [迁移](README.zh.md)

PACE 1.0 仍在开发中。本指南随之扩充：每个预发布版本都会补充需要你修改代码的变化。这里没有列出的内容都保持原样，
无需改动。

## 1.0.0-alpha.1：模块布局

库现在按模块组织。行为和签名都没有变化；变化的是头文件路径、xmake target 和具名模块接口。

### 头文件路径

每个模块有一个伞头 `<pace/<module>.hpp>`，内容头文件位于 `include/pace/<module>/`。最简单的更新方式是为用到的每个
模块包含它的伞头。

| 0.6 | 1.0 |
|:--|:--|
| `<pace/task.hpp>`、`<pace/io_context.hpp>`、`<pace/run.hpp>`、`<pace/cancellation.hpp>`、`<pace/task_group.hpp>`、`<pace/operation.hpp>`、`<pace/this_context.hpp>`、`<pace/blocking.hpp>`、`<pace/platform.hpp>`、`<pace/io_backend.hpp>` | `<pace/runtime.hpp>`，或 `<pace/runtime/…>` 下的同名文件 |
| `<pace/runtime.hpp>`（`pace::runtime` 类） | `<pace/runtime.hpp>` 现在包含整个运行时；只要这个类则用 `<pace/runtime/runtime.hpp>` |
| `<pace/tcp.hpp>`、`<pace/udp.hpp>`、`<pace/ip.hpp>`、`<pace/stream_io.hpp>` | `<pace/net.hpp>`，或 `<pace/net/tcp.hpp>` 等 |
| 用于 HTTP/1.1 的 `<pace/http.hpp>`（`http::app`、`get`、`serve`、客户端） | **`<pace/http1.hpp>`**。`<pace/http.hpp>` 现在是与协议无关的 HTTP 模块 |
| `<pace/http_types.hpp>`、`<pace/http_router.hpp>` | `<pace/http.hpp>`，或 `<pace/http/types.hpp>`、`<pace/http/router.hpp>` |
| `<pace/http_services.hpp>` | `<pace/gateway.hpp>` |
| `<pace/networking.hpp>`、`<pace/extensions.hpp>`、`<pace/application.hpp>` | 已移除：包含你用到的模块头文件，或用 `<pace/pace.hpp>` 包含所有已启用的模块 |
| `<pace/tls.hpp>`、`<pace/dns.hpp>`、`<pace/quic.hpp>`、`<pace/http2.hpp>`、`<pace/http3.hpp>`、`<pace/websocket.hpp>`、`<pace/net.hpp>`、`<pace/pace.hpp>` | 不变 |
| `<pace/detail/…>` | 已移除。它们从来不是公开接口，现在位于库的源码中 |

唯一一处包含语句本身仍能编译、含义却已改变的是 `<pace/http.hpp>`：原本用它来使用 HTTP/1.1 的代码，现在会因为
缺少 `pace::http::app` 或 `pace::http::get` 之类的名字而编译失败。请改为包含 `<pace/http1.hpp>`。

`pace::detail` 命名空间已不存在。直接使用它的代码依赖的是内部实现，没有替代品。

### xmake target

每个模块都是一个独立的静态库，依赖关系明确，因此依赖某一个模块时只会构建该模块及其所需的部分。

| 0.6 | 1.0 |
|:--|:--|
| `pace_runtime`、`pace_net`、`pace` | 不变 |
| `pace_extensions` | 已移除：按需依赖 `pace_tls`、`pace_dns`、`pace_quic` |
| `pace_application` | 已移除：按需依赖 `pace_http1`、`pace_http2`、`pace_http3`、`pace_websocket` |
| — | 新增：`pace_http`，仅头文件，包含与协议无关的 HTTP 类型和路由器；由各 HTTP 模块自动引入 |

网关（`<pace/gateway.hpp>`）目前编译在 `pace_http1` 中。

### 具名模块

`import pace;` 仍然导入所有已启用的内容。现在每个库模块还各有一个具名模块：`pace.runtime`、`pace.net`、
`pace.http`、`pace.http1`、`pace.gateway`、`pace.tls`、`pace.dns`、`pace.quic`、`pace.http2`、`pace.http3`、
`pace.websocket`。每个具名模块只导出自己的名字，因此使用 TCP 的程序要同时导入 `pace.runtime` 和 `pace.net`。
target 仍是 `pace_module`，用 `--modules=y` 构建。[构建选项](../reference/build-options.zh.md)

### 兼容别名

`tcp_stream`、`tcp_listener`、`ipv4_endpoint` 和 `listen_options` 仍可从 `<pace/net.hpp>`
（`<pace/net/aliases.hpp>`）使用，但已弃用（目前还没有编译器警告）：请改用 `pace::tcp::stream`、`pace::tcp::listener`、
`pace::tcp::endpoint` 和 `pace::tcp::listen_options`。它们在 1.0.0-alpha.2 中移除。

## 1.0.0-alpha.2：运行时与网络层

### `task_group::cancel()` 让作用域正常结束

用任务组自己的 `cancel()` 取消后，作用域现在正常返回，不再抛出 `operation_canceled`：有返回值的主体返回它的值，
`void` 主体直接返回。原先在调用 `cancel()` 之后、围绕 `task_group::run` 或 `with_task_group` 捕获
`operation_canceled` 的代码，可以去掉这段处理。有返回值的主体若在产生值之前就被取消，仍会抛出；来自任务组外部的
取消（外层的 `with_cancellation`、截止时间、`io_context::stop()`）照旧传播。

### 移除 0.x 名称

`pace::tcp_stream`、`pace::tcp_listener`、`pace::ipv4_endpoint`、`pace::listen_options` 以及
`<pace/net/aliases.hpp>` 已删除。请分别改用 `pace::tcp::stream`、`pace::tcp::listener`、`pace::tcp::endpoint`
和 `pace::tcp::listen_options`；这四个名字都由 `<pace/net.hpp>` 声明。

### 同方向只允许一个操作，提前检查

TCP 的 `read_some`（或 `close_gracefully`）、`write_all` 或 `listener::accept` 在同方向已有一个操作挂起时再次发起，
现在会立即抛出 `std::logic_error`，与 UDP 一致。此前，第二个读操作可能拿走本属于第一个的数据，第二个写操作可能与
第一个的数据交错。遵守文档中“一读一写”规则的代码不受影响。

### 字节流只有一套字节接口

TCP、TLS 与 QUIC 流以及 UDP 套接字现在只以 `std::byte` span 读写；`char` 与 `std::string_view` 重载已删除。
[`<pace/net/buffer.hpp>`](../reference/net/README.zh.md#as_bytesas_writable_bytes-与-as_text)（由 `<pace/net.hpp>`
包含）在调用处完成转换，不产生拷贝。仍然传入文本的代码会编译失败（无法转换为 `std::span<const std::byte>` 或
`std::span<std::byte>`），不会悄悄改变行为。

| 0.6 | 1.0 |
|:--|:--|
| `stream.write_all("text")`、`stream.write_all(std::string_view(data, size))` | `stream.write_all(pace::as_bytes("text"))`、`stream.write_all(pace::as_bytes(std::string_view(data, size)))` |
| 以 `std::array<char, N>`、`std::vector<char>` 或 `std::span<char>` 调用 `stream.read_some(buffer)` | `stream.read_some(pace::as_writable_bytes(buffer))` |
| `pace::read_exact(stream, std::span<char>(text))`、`tcp::stream::read_exact(std::span<char>)` | `pace::read_exact(stream, pace::as_writable_bytes(text))` |
| `socket.send_to("text", destination)` | `socket.send_to(pace::as_bytes("text"), destination)` |
| `socket.receive_from(std::span<char>(buffer))` | `socket.receive_from(pace::as_writable_bytes(buffer))` |
| `quic_stream.try_read(std::span<char>(buffer))`、`quic_stream.try_write(text)` | `quic_stream.try_read(pace::as_writable_bytes(buffer))`、`quic_stream.try_write(pace::as_bytes(text))` |
| `std::string_view(reinterpret_cast<const char*>(bytes.data()), bytes.size())` | `pace::as_text(bytes)` |
| `template <pace::tls::tls_byte_stream Transport>`、`tls_closeable`、`tls_resettable` | `template <pace::byte_stream Transport>` |

不受影响的有：已经传入 `std::byte` span 的调用、`pace::write(stream, std::string)`、拥有数据的
`pace::read_exact(stream, size)` 与 `stream.read_exact(size)`，以及 UDP 的 `send` / `receive`。

`tls::stream` 的自定义传输层现在必须满足 [`pace::byte_stream`](../reference/net/README.zh.md#byte_stream)：
`read_some(std::span<std::byte>)`、`write_all(std::span<const std::byte>)`、`shutdown_write()`、`close() noexcept`
和 `context() const noexcept`。为 `tls_byte_stream` 编写的适配器改用字节 span，并补上 `shutdown_write()`；只有
`finish_write()` 和 `reset()` 的 QUIC 风格适配器还要加上 `close()`。PACE 自己的流新增的成员是：`tcp::stream`（FIN）、
`tls::stream`（`close_notify`）和 `quic::stream`（FIN）上的 `shutdown_write()`，以及 `quic::stream::close()`。
