# 所有权与热路径审查（2026 年 11 月 16–18 日）

[English](ownership-review-2026-11.md) · [性能历史](README.zh.md)

本次审查涵盖运行时调度与工作线程所有权、HTTP 派发与路由、TLS 配置、DNS 查询以及 QUIC 泵（pump）。
所有改动都保持了现有的上下文亲和性契约和关闭契约。基准测试的计时描述的是本地隔离的组件，
而不是端到端的网络吞吐量。

## 改动

- `http::make_handler` 按值保存函数指针和平凡的空可调用对象。它们的调用协程持有自己的副本，直到嵌套的处理函数结束。
  这条路径因此去掉了共享可调用对象的内存分配和引用计数，同时保留了惰性调用和异常传播。
  有状态和非平凡的可调用对象仍使用共享所有权：被拷贝的处理函数必须看到同一份可变状态，而且挂起中的调用必须在
  适配器销毁后依然存活。该优化调用的是原始的调用运算符，而不是用户自定义的、到函数指针的任意转换。
- `http_dispatch::completion_awaiter` 借用由正在等待的协议协程所持有的派发状态。`close_http_dispatch`
  从嵌套作用域中借用同一个所有者。两者都不需要自己的 `shared_ptr`。分离的请求处理函数仍保留所有权，
  因为它们的生命周期可能长于一个已关闭的连接。
- 路由条目在一个有序 vector 中按路径分组。查找复杂度为 `O(log N + M)`，其中 `N` 为路由数，`M` 为匹配路径上的方法数，
  而不是扫描全部路由。在每个路径内，`Allow` 保留注册顺序；HEAD 回退、显式 HEAD 优先、排除查询串、精确路径匹配、
  写时复制的路由表以及被移出后的路由器复用都保持不变。注册可能会移动 vector 中的元素；它是一项在开始服务之前进行的操作。
- 反应器在各次迭代之间复用两个收件箱排空用的 deque。互斥锁和待处理标志的顺序不变，包括从空到非空时的唤醒。
  生产者/消费者路径仍以移动方式转移任务和回调。这减少了分配器的工作量；本地入队计时并未显示出一致的吞吐量提升。

- QUIC 现在在所有受支持的 POSIX 平台上使用 PACE 的回调定时器。侵入式等待者避免了链表节点的分配，并把后续操作排入反应器队列。
  ngtcp2 后端使用按连接划分的进度信号、唯一所有的流缓冲区、有界的数据包批次以及有界的发送/接收窗口。它的连接路由表
  借用与反应器亲和的状态（在销毁时移除），从而避免对每个收到的数据包都锁定一次弱指针。后台泵使用弱引用。这是一项调度和所有权方面的改动。
  [传输层对比](../../../benchmarks/results/quic-backends-2026-11-18/README.md)测量了两个后端。

## 有意保留的所有权

| 领域 | 所有权/生命周期结论 |
|---|---|
| 工作线程 | `runtime` 已经通过 `unique_ptr` 持有各个上下文；线程借用上下文，并在返回前 join。这里不需要共享引用计数。 |
| 跨线程提交 | 传入的任务队列和回调队列本来就以移动方式转移所有权。把它们换成共享的任务节点只会增加开销；因此没有做这种改动。 |
| 路由表 | 连接处理函数的各个副本共享不可变的路由表；注册时副本会分离。为每个连接深拷贝会分配内存并复制所有路由。对同一个路由器对象的注册仍需要外部同步。 |
| 有状态处理函数 | 实例可以在多个工作线程之间共享。引用计数保护的是生命周期，**而不是**捕获的可变状态；应用必须自行同步这些状态。 |
| 回调定时器 | 句柄的生命周期可能长于 `io_context`。共享注册表/弱句柄这一对设计，使得在上下文销毁后仍能安全取消，并能递归清理捕获的对象。使用裸注册表指针会违反这一契约。 |
| TLS | 在公开的上下文销毁后，流和 SNI 映射仍保留配置。配置可以在多个工作线程之间共享；冻结和修改使用现有的互斥锁。 |
| DNS | 解析器的销毁和套接字的移除可能先于取消的后续操作发生。查询和套接字的所有者必须在这些后续操作中存活，包括描述符被复用的情况。 |
| QUIC | 连接和流保留其父对象；后台泵使用弱引用，以免让已被丢弃的引擎继续存活。跨越挂起点使用裸指针是不安全的。 |
| HTTP/2 与 HTTP/3 | 分离的应用处理函数在协议/会话拆除后仍可能处于挂起状态。它们只保留派发状态；关闭守卫会清除借用的传输层唤醒回调。 |

## 有待性能剖析的其他候选项

以下各项已经检查过，但在本次改动中尚未确定为主要瓶颈。进一步的改动需要针对具体工作负载的测量：

- 根任务注册表以及休眠任务的取消已在
  [运行时与套接字后续研究](../../../benchmarks/results/runtime-network-2026-11-18/README.md)中测量。
- DNS 初始化会同步读取解析器/hosts 配置。共享已初始化的解析器通道会改变取消和并发语义；
  大量查询的工作负载应单独测量这项开销。
- HTTP 解析/序列化以及带缓冲的消息体仍会拷贝和分配内存。在替换缓冲区或修改所有权 API 之前，
  应先测量响应大小、流式用法、TLS 加密和套接字背压。

## 验证

- GCC 13、C++20、全部协议：12 个正确性测试套件，包括 HTTP/2 和 HTTP/3 的断开/取消以及延迟处理函数路径。
- GCC 13 debug，ASan + UBSan + 泄漏检测：同样的 12 个套件。
- 路由器回归测试覆盖了无序注册、精确路径匹配、HEAD 与 Allow 的顺序、写时复制、有状态适配器共享、惰性异常、
  无状态协程的生命周期以及用户自定义可调用对象转换的语义。
- 运行时回归测试覆盖了并发混合的 post/spawn 生产者、反复休眠/唤醒、取消和销毁。
- 具名模块检查：Clang 18/libstdc++ 13，C++20 默认/core 以及 C++23 全部协议，包括头文件/import 混用的跨翻译单元调用。
  GCC 13 在导出 using 声明的 import 上的局限记录在构建指南中。

参见[原始测量数据与复现方法](../../../benchmarks/results/module-hotpaths-2026-11-16/README.md)。

### QUIC 后端与新版编译器的后续验证

  循环使用 160 个流（超过流数量上限和连接窗口），并在不同后端之间交换 192 KiB 的二进制负载，每个后端都分别充当服务器。
